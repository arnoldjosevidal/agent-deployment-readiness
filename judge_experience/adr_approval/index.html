It controls the action—not every step of the agent’s legitimate task.

API flow · current implementation
What happens, in order
Local same-origin HTTP

        
  1. Launchrun_approval_demo.py starts the server on 127.0.0.1.
  2. AuthenticateBrowser posts to /api/login; backend creates a session and CSRF token.
  3. Start a fixture/api/lab/runs/start stores the selected scenario, mode and idempotency key.
  4. Build turnScenarioLab packages messages and tool schemas for local ScriptedModel.
  5. Propose actionA fixture frame returns a structured tool name and arguments.
  6. EvaluateApprovalService.propose binds the action to the frozen local policy design.
  7. BranchALLOW executes a fictional tool; BLOCK records denial; REQUIRE_APPROVAL persists a pending action.
  8. Human decisionAuthenticated approve/reject posts the immutable action hash and CSRF token.
  9. ResumeThe result is added as a tool message; the next ScriptedModel frame produces the fixture’s final response.
  10. PersistSQLite stores run/action state and hash-linked audit events. The app verifies the chain before display.
  11. Provider boundaryThis build sends no request. Historical Nebius requests used NVIDIA Nemotron-3.5-Lightning; V2 live validation is pending.

      

      
Scale, honestly separated
Prototype today. Enterprise path proposed.
CURRENT PROTOTYPE
  • One local operator, one process, SQLite.
  • Fictional tools and deterministic fixture turns.
  • Loopback-only server; session + CSRF.
  • Hash-linked local audit; no HA or throughput claim.
PROPOSED PRODUCTION ARCHITECTURE
  • Agent middleware/interceptor with explicit capability identity.
  • Policy service with versioned organization and agent rules.
  • Approval service, signed decisions, queue and idempotent workers.
  • Tenant-isolated durable database and append-only event storage.
  • Secret manager, RBAC, observability, alerts and audit export.
  • Horizontal scaling only after load, latency and failure testing.
  • Fail-closed behavior for policy or evidence uncertainty.
This is a reasoned design path, not a capability or benchmark claim. Governance evidence may help an organization design audit workflows; ADR is not certified for GDPR, the EU AI Act or other frameworks.

      
Implementation boundary
What works · what is historical · what is still open
WHAT WORKS IN THIS DEMO
Fixture-driven ALLOW, BLOCK and REQUIRE_APPROVAL; authenticated human choice; fictional effects; scripted continuation; local audit.
WHAT HAS HISTORICAL EVIDENCE
Six exploratory live Nebius/NVIDIA requests in three workflows, shown read-only with stated limitations.
WHAT STILL NEEDS LIVE VALIDATION
Reproducible V2 provider integration, B1 token-binding requirements, and model-generated action behavior in this candidate.
WHAT IS PLANNED FOR PRODUCTION
Multi-user identity, tenant isolation, service deployment, managed storage, monitoring and operational testing.
